# Design

## Context

См. proposal.md — Why. Шаблон сервера уже содержит тестовую инфраструктуру (`tests/common/{common,unit,e2e}-spec.ts.t`, `vitest.{base,unit,e2e}.config.mjs.t`, `tests/unit/setup.ts.t`, `tests/e2e/setup.ts.t`, `tests/__mocks__/e2e.ts.t`), но раздел «Тестирование» в `AGENTS.md.t` описывает её скупо, а гайда тестов нет. Эталон — `apps/webview-event-analyse-server/AGENTS.md` (раздел 🧪 Тестирование) и `apps/webview-event-analyse-server/tests/README.md` в `/www/lmru/projects/payment/pof/lmru-payment-pof-webview_event_analyse/`.

## Goals / Non-Goals

**Goals:**

- Перенести правила тестирования из AGENTS.md эталона в шаблон сервера (AGENTS.md.t) в том же аккуратном виде.
- Дать сгенерированным проектам гайд тестов (tests/README.md.t) по структуре эталонного README.
- Задокументировать тесты самого генератора (tests/README.md + раздел в корневом AGENTS.md).

**Non-Goals:**

- Component-слой тестов в шаблоне (есть в эталоне — отдельное решение).
- Изменение runtime-кода тестовой инфраструктуры шаблонов (конфиги vitest, setup-файлы) — только если текст правил на них ссылается некорректно.
- Реорганизация тестов генератора (factory/runner specs остаются как есть).

## Decisions

- **D1: Агрессивность переноса.** В AGENTS.md.t переносятся формулировки правил эталона, но только те, что соответствуют фактическому составу шаблона (unit + e2e). Упоминания component-слоя и реального ClickHouse из эталона не переносятся — в шаблоне e2e поднимает `Root.$run()` и использует Unimock.
- **D2: Гайд как документация.** `tests/README.md.t` пишется как шаблон документации (не пример кода): условие в `to:` без гейта `CUT_EXAMPLES`. Содержимое адаптируется с эталонного README: убираются ClickHouse-специфика и component-разделы, добавляется дисклеймер, что это стартовый гайд, который проект развивает сам.
- **D3: unit-spec уже соответствует эталону.** `tests/common/unit-spec.ts.t` в шаблоне идентичен эталонному `UnitSpec` (`httpServer = null`) — правки не требуются; правила просто ссылаются на него.
- **D4: Регенерация фикстур обязательна.** Изменение AGENTS.md.t и добавление tests/README.md.t меняет манифест генерации → после правок прогнать `node tests/__fixtures__/generate-manifests.mjs`, затем `pnpm test`; интеграционный тест golden-матрицы валидирует согласованность.
- **D5: Лёгкая форма для репозитория.** `tests/README.md` генератора — один компактный документ (стек, два spec-файла, фикстуры, команды); в корневом `AGENTS.md` — только раздел с 3–5 строками и ссылкой на гайд.

## Risks / Trade-offs

- **Расхождение гайда с эволюцией проектов:** сгенерированный README — срез на момент генерации; проекты (как эталон) будут развивать его сами. Смягчается дисклеймером в гайде (D2).
- **Двойная поддержка правил** (AGENTS.md.t vs tests/README.md.t частично дублируются): AGENTS.md.t держит краткие правила, README — развёрнутый гайд; в AGENTS.md.t добавляется ссылка на `tests/README.md`.
- **Диффы golden-фикстур** затронут все 5 кейсов (AGENTS.md в корне и server, новый README в server) — ожидаемо, регенерация по D4.
