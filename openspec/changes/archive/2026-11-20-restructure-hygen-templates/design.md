# Design

## Context

Генератор живёт в `_templates/app/create/` — 185 EJS-файлов одной плоской папкой с префиксами `NNNNN.MM_`. Все шаблоны имеют явный `to:` во frontmatter (имена файлов не участвуют в маппинге вывода). Конфигурация — через шаблон `00000.00_config.ejs.t`, чьи EJS-присваивания несуществующих переменных «утекают» в глобалы процесса и так становятся видны остальным файлам. Используется `@biorate/hygen 0.1.0` (форк jondot/hygen 6.2.11).

Проверенные факты механики `@biorate/hygen` (по `dist/cjs/src`):

- `params.js`: действия перечисляются через запятую (`hygen create root,client,server`), исполняются по порядку в одном процессе; поддерживается `action:subaction`.
- `render.js`: файлы действия выбираются `ignore-walk` (рекурсивно, кроме служебного списка `prompt.js`, `index.js`, …) и сортируются `localeCompare` по полному пути.
- `context.js`: `config.helpers` может быть **функцией** `(locals, config) => helpers` — вызывается перед каждым рендером frontmatter и тела.
- `ops/add.js`: расширение `.t` срезается в mirror-режиме по умолчанию; при явном `to:` расширение ни на что не влияет.
- `config-resolver.js`: `.hygen.js|.hygen.cjs|.hygen.mjs|.hygen.ts` ищется от cwd вверх по дереву и мержится в конфиг.
- `runner.js`: ошибки рендера (например, throw в фабрике хелперов) прерывают прогон.

## Goals / Non-Goals

**Goals:**

- Структура `_templates/create/{root,client,server,help}/` с вложенностью «как целевое приложение».
- Конфигурация и валидация — в фабрике хелперов `.hygen.js` (вариант A: шаблоны обращаются `h.*`).
- Убрать нумерацию, `--hygen`, удаление артефактов; добавить guard и обязательный `--root`.
- Сохранить байт-в-байт эквивалентность сгенерированного вывода (кроме осознанных отличий: `.hygen.js` в цели, деп `@biorate/hygen`, отсутствие чистки).

**Non-Goals:**

- Доработки самой библиотеки `@biorate/hygen` (frontmatter-приоритеты и т.п.) — отложено.
- Копирование `_templates/`/`doc/` в целевую папку — шаблоны живут только в генераторе (будущем npm-модуле).
- Публикация генератора как npm-модуля — отдельная последующая работа.
- Изменение содержимого генерируемого кода (стека, слоёв, тестов).

## Decisions

### D1. Действия вместо одного действия `app create`

`_templates/create/{root,client,server}`; вызов `hygen create root,client,server` или подмножеством. Альтернатива — одно действие с подпапками: отвергнуто, т.к. не даёт частичной генерации и сохраняет кучу при сортировке. Комма-список действий исполняется в одном процессе, но от глобального состояния между действиями не зависим (см. D2) — каждое действие самодостаточно.

### D2. Конфигурация — фабрика в `.hygen.js` (вариант A)

`module.exports.helpers = (locals, config) => {...}` вычисляет и **возвращает** все значения как хелперы: `h.ROOT`, `h.APP_NAME`, `h.APP_DESCRIPTION`, `h.SERVER_NAME`, `h.CLIENT_NAME`, `h.CLIENT`, `h.SERVER`, `h.CUT_EXAMPLES`, `h.ADD_WEB_SOCKET`, `h.platform`, `h.root`, `h.defined`, `h.stringify`, `_`. Валидация обязательных флагов (`--app-name`, `--app-description`) — внутри фабрики, до любых вычислений.

`CLIENT` и `SERVER` **вычисляются из списка действий**: фабрика получает позиционные аргументы через `locals._` (`['create', 'root,client,server']`), разбивает второй элемент по запятой и проверяет вхождение `client`/`server`. Это позволяет удалить флаги `--client`/`--server`, сохранив условные ветки шаблонов (40 клиентских зависимостей в корневом `package.json`): состав генерации теперь выражается самим списком действий.

Альтернативы: оставить конфиг-шаблон (отвергнуто: зависит от утечки в глобалы — хрупко и зависит от порядка); писать в `globalThis` из фабрики (отвергнуто пользователем: сохраняет неявный глобальный стиль, тела всех 185 файлов переписываются всё равно ради `h.*` — выбран единый явный доступ); оставить флаги `--client`/`--server` (отвергнуто: их роль исполняет список действий, дублирование создаёт противоречивые состояния — действие `client` выбрано, флаг не передан).

Замечание по совместимости EJS: внутри `with(locals)` имя `h` уже резолвится, поэтому `h.CLIENT` в условных блоках (`<% if (h.CLIENT) { %>`) и интерполяциях работает без изменений механики.

### D9. Интерактивные параметры — `prompt.js` в каждом действии

Механика `@biorate/hygen` (`src/prompt.js`): до рендера файлов действия движок ищет в actionfolder `prompt.js` (или `index.js`/`*.ts`) и вызывает `hooksModule.prompt({ prompter, args, h })`; результат вливается в `args` и **виден фабрике хелперов** наравне с CLI-флагами. Используем свой хук вместо дефолтного массива вопросов:

```js
// _templates/create/{root,client,server}/prompt.js
module.exports.prompt = async ({ prompter, args }) => {
  const missing = (k) =>
    args[k] === undefined || args[k] === null || args[k].length === 0;
  if (!process.stdin.isTTY) return {}; // CI: без вопросов, валидацию делает фабрика
  return prompter.prompt(
    [
      missing('app-name') && { type: 'input', name: 'app-name', message: 'App name:' },
      missing('app-description') && {
        type: 'input',
        name: 'app-description',
        message: 'App description:',
      },
      missing('cut-examples') && {
        type: 'confirm',
        name: 'cut-examples',
        message: 'Cut examples?',
      },
      missing('add-web-socket') && {
        type: 'confirm',
        name: 'add-web-socket',
        message: 'Add WebSocket?',
      },
    ].filter(Boolean),
  );
};
```

Решения внутри D9:

- **TTY-guard обязателен**: движок вызывает `prompt()` безусловно; в CI/скриптах без него enquirer завис бы. Не-TTY → `{}` → фабрика валидирует и падает с ошибкой.
- **Вопросы только о недостающем** — переданные флаги не переспрашиваются (фильтр `missing`).
- **`--root` не спрашивается** — папка назначения слишком важна для случайного интерактивного ввода; guard и предсказуемость важнее UX.
- **`client`/`server` не спрашиваются** — состав выражен списком действий (D2); вопрос создал бы противоречие («действие client выбрано, ответ — нет»).
- **`prompt.js` в каждом из трёх действий** — при одиночном запуске (`hygen create client`) параметры всё равно запросятся; фильтр защищает от повторных вопросов при комма-запуске.
- Позиционные `args._` доступны и в промпте, но деривация `CLIENT`/`SERVER` живёт только в фабрике — единое место конфигурации.

### D10. Тестирование через embedding API `runner()` на стеке @biorate/vitest + @biorate/vitest-spec

`@biorate/hygen` экспортирует типизированный `runner(argv, config): Promise<RunnerResult>` (`RunnerConfig`: `cwd`, `templates`, `exec`, `logger`, `createPrompter`, `helpers`, `interactive`, …). Генератор тестируется как библиотека, без спавна CLI.

**Стек тестов** (референс — монорепо `biorate/core`, пакеты `@biorate/vitest` 2.4.5 и `@biorate/vitest-spec` 2.2.5):

- `@biorate/vitest` — OOP-декораторы `@suite`/`@test`, модификаторы (`@skip`, `@timeout`, `@repeats`), lifecycle (`beforeAll`/`before`/`after`/`afterAll`); peerDeps `vitest >=2`, `reflect-metadata`, `allure-js-commons`, `allure-vitest` — тот же стек, что в сгенерированных приложениях.
- `@biorate/vitest-spec` — базовый класс `Spec`: `this.exactly()` (deep-equality) для сравнения с golden-манифестами, общий каркас.
- Конфигурация — по паттерну monorepo biorate: корневой `vitest.config.mjs` с `globals: true`, `setupFiles: ['reflect-metadata']`, `include: ['**/*.{test,spec}.{js,ts,mjs}']`; Allure-репортер (`allure-vitest/setup`) подключается по образцу `packages/@biorate/vitest/vitest.config.ts` из core.

**Уровни тестов:**

- **Фабрика `.hygen.js`** — юнит-тесты чистой функции (`@suite`-класс): деривация `CLIENT`/`SERVER` из `locals._`, guard (точное совпадение realpath), валидация обязательных флагов.
- **Интеграционные прогоны** — `runner(['create', …], { cwd: repoRoot, templates: '<repo>/_templates', exec: mockExec, logger: captureLogger, createPrompter: () => mockPrompter })` в `tmp/`-каталогах (создание/очистка в `beforeAll`/`afterAll`); ассерты по файловой системе (`success`, статусы, дерево файлов, содержимое ключевых файлов).
- **Промпты** — `createPrompter` подменяется моком: перехват вопросов (фильтрация только missing-параметров), программные ответы; TTY-ветка через стаб `process.stdin.isTTY`.
- **a-before/z-after** — `exec`-мок копит команды: ассерты порядка и содержимого (`prettier --write`, `chmod ug+x`) без реального исполнения.
- **Golden-фикстуры**: манифесты деревьев файлов + хэши содержимого ключевых файлов для матрицы случаев, коммитятся в `tests/__fixtures__/`; сравнение через `this.exactly()`. Генерируются один раз на этапе верификации (после ручного diff против `ref-old`, задача 6.1) и дальше служат регрессионным эталоном. Хранение сырого `ref-old` от старого кода в CI не требуется.
- **Инфраструктура**: devDeps `@biorate/vitest`, `@biorate/vitest-spec`, `vitest`, `reflect-metadata`, `allure-js-commons`, `allure-vitest` + корневой `vitest.config.mjs` + каталог `tests/` — первая тестовая сущность в репо генератора; одновременно задел под будущий npm-модуль.

Альтернативы: спавн CLI в subprocess (медленнее, сложнее мокать промпты/exec); голый vitest без декораторов (отход от экосистемного стека biorate); только ручная diff-верификация (не регрессионная). Отвергнуты.

### D3. Упорядочивание без нумерации

Порядок рендера = `localeCompare` полного пути внутри действия. Имена `a-before.t` (sh: "") и `z-after.t` (prettier --write `<ROOT>`; на linux `chmod ug+x <ROOT>/.husky/*`) гарантированно первый/последний: `'a-' < 'ap'` (для каталогов `apps/`) и `'z' > …`. Внутри остальных файлов порядок не важен: `to:` явные, `unless_exists`/`force`/`skip_if` порядка не зависят, конфигурация доступна каждому файлу независимо (D2).

`z-after.t` объединяет нынешние 00183/00184 (обе ветки `h.platform`); `a-before.t` — плейсхолдер.

### D4. Guard точного совпадения

В фабрике `.hygen.js`, до возврата хелперов:

```js
const tmplRoot = path.resolve(path.dirname(config.templates)); // <repo>/_templates
const root = fs.realpathSync.native(path.resolve(locals['root']));
const base = fs.realpathSync.native(tmplRoot);
if (root === base) throw new Error(...);
```

Только точное совпадение (решение пользователя): `--root=tmp` внутри репо работает; `--root` на родителя шаблона тоже разрешён. Использование `config.templates` (а не `process.cwd()`) корректно и для будущего npm-модуля (шаблон в `node_modules/@scope/pkg/_templates`). Guard срабатывает на первом рендере — до записи файлов.

### D5. Удаление `--hygen` и отказ от чистки

- Шаблон `00006.00_.hygen.js.ejs.t` остаётся как `root/.hygen.js.t`, `to:` безусловный, содержимое — новая фабрика (D2/D4), чтобы сгенерированное приложение могло запускать собственные hygen-генераторы.
- `00017 package.json.t`: деп `"hygen": "6.2.11"` (под гейтом HYGEN) → безусловный `"@biorate/hygen": "^0.1.0"` (только если `--server`? нет — деп живёт в корневом `package.json` монорепо, пишется безусловно, как раньше под гейтом).
- Все ветки `HYGEN ? … : …` и строки `fse remove` из after-all выпиливаются. Никаких удалений генератором — никогда.

### D6. Выпиливание гейтов `h.server()`/`h.client()` из `to:`

~181 место: `<%= h.server(`${ROOT}/apps/${SERVER_NAME}/...`) %>` → `<%= `${h.ROOT}/apps/${h.SERVER_NAME}/...` %>`. Хелперы `server`/`client` из `.hygen.js` удаляются; `h.root` сохраняется (используется в общих шаблонах). Хелпер `hygen` удаляется вместе с флагом (D5).

### D7. help-действие

`_templates/app/help/index.ejs.t` → `_templates/create/help/index.t`; текст справки обновляется (действия root/client/server, обязательный `--root`, флаги без `--hygen`).

### D8. Верификация — diff старого и нового вывода

Эталон: до миграции сгенерировать `hygen app create` (старый код, из git-рабочей копии до изменений) в `tmp/ref-old/…` для матрицы флагов: `--client --server`, только `--client`, только `--server`, `± --cut-examples`, `± --add-web-socket`. После миграции — те же матрицы через `hygen create root,client,server` в `tmp/ref-new/…`. Сравнение `diff -r` с ожидаемыми осознанными отличиями: `tmp/ref-new/.hygen.js` (новая фабрика), корневой `package.json` (`@biorate/hygen`), отсутствие веток чистки (влияло только на старый in-place, на вывод с `--root` не влияло). Плюс негативные проверки: без `--root`, без `--app-name`, `--root` = корень репо (guard).

## Risks / Trade-offs

- [localeCompare-порядок зависит от локали/платформы] → Позиции `a-before`/`z-after` устойчивы к любой разумной локали (`a-`/`z-` крайние); в tasks — smoke-проверка на целевой платформе (linux/mac). При необходимости вернуться к доработке `@biorate/hygen` (frontmatter-приоритет) — изолировано в двух файлах.
- [Массовая правка 185 файлов — риск опечаток в `h.*`] → Погашается D8 (diff-матрица): любое расхождение вывода ловится сравнением, а не ручным ревью.
- [Guard не защищает от не-точных пересечений (родитель/потомок)] → Осознанное решение пользователя; in-place режим всё равно исчез (обязательный `--root`), риск сводится к намеренному `--root` на родителя репо — задокументировать в справке.
- [`.hygen.js` ищется от cwd вверх] → Генерация всегда запускается из корня репо шаблона (или будущего модуля), где `.hygen.js` лежит рядом с `_templates/`; для `npx hygen` из подкаталогов — задокументировать запуск из корня.
- [`--root=tmp` оставляет артефакты генерации в репо] → `tmp/` уже в `.gitignore` (проверить); поведение сохранено сознательно для локальных тестов.

## Migration Plan

1. Зафиксировать эталонный вывод старого генератора (D8, матрица флагов) — из git-истории/рабочей копии до правок.
2. Реструктуризация каталогов + переименование `.t` (git mv, сохранение истории) + снятие префиксов.
3. Переписать `.hygen.js` (фабрика + guard + валидация), обновить `root/.hygen.js.t` и `package.json.t`.
4. Переписать тела/`to:` шаблонов на `h.*`, убрать гейты, вписать `a-before.t`/`z-after.t`.
5. Обновить `help/index.t`, README, AGENTS.md; удалить `.scripts/renumerate-templates.js`.
6. Прогнать D8-матрицу, добиться ожидаемого diff; негативные сценарии.
7. Rollback: вся миграция — один коммит/ветка; откат `git revert` возвращает плоскую структуру и старые команды.
