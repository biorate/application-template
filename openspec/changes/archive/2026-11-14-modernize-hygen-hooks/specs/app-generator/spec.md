# Spec Delta

## ADDED Requirements

### Requirement: Классовая форма action hooks в действиях генератора

Каждое действие генератора (`root`, `client`, `server`) MUST содержать hook-файл в классовой TS-форме `hooks.ts` (дефолт-экспорт класса, самодостаточные минимальные интерфейсы) с async-методом `prompt({ prompter, args })`; legacy-файлы `prompt.js` в папках действий отсутствуют. Секция `prompt` запрашивает только параметры, отсутствующие в CLI-аргументах; в не-интерактивном режиме (non-TTY) вопросы не задаются — валидацию выполняет фабрика хелперов.

#### Scenario: Интерактивный ввод недостающих параметров

- **WHEN** запуск `hygen create` в TTY без флагов `--app-name`/`--app-description`/`--cut-examples`/`--add-web-socket`
- **THEN** hook-класс запрашивает только недостающие параметры, ответы становятся переменными шаблонов; переданные флаги не переспрашиваются

#### Scenario: Не-интерактивный режим

- **WHEN** запуск в non-TTY (CI) без флагов
- **THEN** вопросы не задаются, прогон завершается валидационной ошибкой фабрики хелперов, перечисляющей недостающие параметры

### Requirement: Доставка фабрики хелперов в сгенерированную цель

Действие `root` MUST создавать `.hygen.ts` (фабрика хелперов TS с именованным экспортом `export const helpers`, guard'ом и валидацией) в корне сгенерированного репозитория — через шаблон `_templates/create/root/$ROOT$/.hygen.ts.t` (`mirror: true` + `unless_exists: true`). Повторная генерация не перезаписывает существующий `.hygen.ts` цели.

#### Scenario: Первый запуск

- **WHEN** `hygen create root,client,server` выполняется в пустую цель
- **THEN** `<root>/.hygen.ts` создаётся, содержимое идентично фабрике репозитория-шаблона

#### Scenario: Повторная генерация

- **WHEN** генерация выполняется в цель, где `.hygen.ts` уже существует
- **THEN** существующий файл не перезаписывается (`unless_exists`)

### Requirement: Чистота фабрики хелперов

Фабрика хелперов (`.hygen.ts` репозитория и её шаблон `.hygen.ts.t` в цели) MUST использовать именованный экспорт `export const helpers` (контракт движка: `export default` ломает резолв — резолвер спредит namespace модуля) и MUST быть байт-в-байт синхронна с шаблоном доставки (оба файла отформатированы repo-prettier, т.к. prettier в `z-after.t` переформатирует цель).

#### Scenario: Синхронность фабрик и контракт экспорта

- **WHEN** инспекция `.hygen.ts` и шаблона фабрики
- **THEN** обе фабрики содержат именованный экспорт `helpers`, содержимое фабрик байт-в-байт синхронно (sync-тест в `factory.spec.ts`)

### Requirement: Сохранение генерируемого результата (с оговоркой доставки фабрики)

Доставка `.hygen.ts` — единственное изменение состава файлов цели: для любой комбинации действий и флагов состав, расположение и содержимое остальных файлов MUST оставаться идентичными golden-фикстурам; манифесты фикстур дополняются хэшем `.hygen.ts`.

#### Scenario: Diff-матрица с учётом фабрики

- **WHEN** интеграционный прогон генерации (`pnpm test`) после миграции
- **THEN** diff-матрица пуста с учётом добавленного `.hygen.ts` в манифестах; для действий без `root` фабрика в цели отсутствует
