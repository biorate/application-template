# Design

## Context

Сейчас фиксация жизненного цикла root-действия сделана шаблонами-хаками алфавитного порядка: `a-before.t` (`sh: ""`, no-op) и `z-after.t` (`sh:` prettier + chmod husky, с EJS-условием `h.platform === 'linux'`). Движок `@biorate/hygen@0.5.1` поддерживает проектные хуки через именованный экспорт `hooks` в `.hygen.ts` (`normalizeProjectHooks` допускает `beforeAll/beforeEach/afterEach/afterAll`; контекст — `{ cwd, args, h, logger, dry }`). Ключевой дефект текущей схемы: z-after исполняется в конце действия root — до записи client/server, поэтому клиент и сервер не форматируются. См. proposal.md — Why.

Смежные факты: `h.platform` используется только в `z-after.t`; runner-фикстуры капчерят `sh:`-команды в `*.exec.json` — после миграции prettier/chmod исполняются в action-хуке и в капчур не попадают. Зависимость: дельта спеки строится поверх `drop-target-hygen-config`.

## Goals / Non-Goals

**Goals:**

- Перенести пост-обработку цели в action-хук `afterAll` класса `hooks.ts` действия root; убрать шаблоны-хаки и хелпер `platform`
- Защитить от сайд-эффектов при упавшей генерации (guard на пустые results)

**Non-Goals:**

- Проектные хуки (`hooks` в `.hygen.ts`) и `beforeAll`/`beforeEach`/`afterEach` — без сценариев не добавляются
- Форматирование client/server действием root (гранулярность z-after сохраняется)
- Новый механизм композиции locals: фабрика `helpers(locals, config)` остаётся единственным способом трансформации CLI-args в `h.*`; `localsDefaults` движка не умеет производные значения — изменений нет, только фиксация в документации
- Изменение состава/содержимого генерируемых файлов

## Decisions

1. **Action-хук `afterAll` в `_templates/create/root/hooks.ts`, а не проектный хук в `.hygen.ts`.** Решение пользователя: пост-обработка относится только к root-действию — хук живёт в классе action-хуков рядом с params-схемой. Гранулярность прежнего z-after сохраняется (prettier в конце действия root; client/server генератором не форматируются). Проектный уровень в `.hygen.ts` (run-scoped, после всех действий) рассмотрен и отклонён как избыточный для root-scoped обязанности.
2. **Проверка платформы через `process.platform !== 'win32'` вместо `=== 'linux'`.** chmod валиден на всех unix (macOS тоже генерирует husky-хуки); прежнее условие `=== 'linux'` было уже в z-after, но шире и корректнее — на macOS сейчас биты не ставятся.
3. **exec через `child_process.execSync` c `stdio: 'inherit'` для prettier** — ошибка форматирования видна в выводе генерации и валит прогон; chmod — `stdio: 'ignore'` + guard `fs.existsSync(<root>/.husky)` (в комбинациях без root-действия или без husky хук не должен падать).
4. **`h.platform` удалить, не оставлять «про запас»** — мёртвый хелпер в фабрике; при потребности возвращается тривиально.

## Risks / Trade-offs

- [Ошибка prettier в хуке валит генерацию после записи файлов] → Осознанно: частично сгенерированная цель — худший исход, чем явная ошибка; повторная генерация идемпотентна.
- [exec.json-фикстуры теряют captured prettier/chmod] → Контракт фикстур — капчур frontmatter `sh:`-команд; хуки движком не капчерятся. Сценарий «Отсутствие шаблонов-хаков» фиксирует отсутствие prettier/chmod в капчуре.
- [Переформатирование файлов client/server изменит их sha256] → Не актуально при action-гранулярности: prettier в конце root-действия форматирует только записанные к этому моменту файлы (как прежний z-after); манифесты всё равно регенерируются.
- [Дельта спеки конфликтует с незакоммиченной дельтой drop-target-hygen-config] → Последовательность: архивация drop-target до применения настоящего изменения (зафиксировано в proposal).

## Migration Plan

Одна ветка: удалить шаблоны-хаки → добавить `afterAll` в класс `hooks.ts` действия root, убрать `platform` → правки тестов/доки → регенерация фикстур → `pnpm test` + контрольная генерация. Откат — revert коммита.
