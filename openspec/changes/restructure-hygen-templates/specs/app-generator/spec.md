# Spec Delta

## Purpose

Поведение генератора приложений: команда `create` собирает монорепозиторий (root, client, server) из Hygen-шаблонов в указанную папку, с конфигурацией через фабрику хелперов, защитой репозитория шаблона и фиксированными точками до/после генерации.

## ADDED Requirements

### Requirement: Команда create с комбинируемыми действиями

Генератор SHALL поддерживать команду `hygen create <actions>`, где `<actions>` — одно действие или список через запятую из `root`, `client`, `server`, исполняемых по порядку перечисления. Пример полного сценария: `hygen create root,client,server`.

#### Scenario: Полная генерация одной командой

- **WHEN** пользователь выполняет `hygen create root,client,server --root=<dir> --app-name=<name> --app-description=<desc>`
- **THEN** в `<dir>` создаётся полный монорепозиторий: корневые файлы, `apps/<name>-client`, `apps/<name>-server`

#### Scenario: Генерация подмножества действий

- **WHEN** пользователь выполняет `hygen create client --root=<dir> --app-name=<name> --app-description=<desc>`
- **THEN** генерируются только файлы, относящиеся к клиентскому приложению, в `apps/<name>-client`

#### Scenario: Действие без обязательных флагов

- **WHEN** пользователь выполняет `hygen create client --root=<dir>` без `--app-name` в не-интерактивном окружении (без TTY)
- **THEN** генерация завершается ошибкой валидации до записи каких-либо файлов этого действия

### Requirement: Действия определяют состав генерации

Принадлежность генерируемых частей SHALL определяться исключительно списком действий в команде. Флаги `--client` и `--server` SHALL NOT поддерживаться. Значения `CLIENT` и `SERVER`, используемые шаблонами (например, для условных зависимостей корневого `package.json`), SHALL вычисляться из списка действий: действие `client` в списке → `CLIENT = true`, действие `server` → `SERVER = true`.

#### Scenario: Зависимости корневого package.json следуют списку действий

- **WHEN** выполняется `hygen create root,client --root=<dir> --app-name=<name> --app-description=<desc>`
- **THEN** корневой `package.json` содержит клиентские зависимости и не содержит серверных зависимостей

#### Scenario: Флаг --client отклоняется

- **WHEN** пользователь передаёт `--client` в команде `create`
- **THEN** генерация завершается ошибкой: флаг не поддерживается, состав определяется списком действий

### Requirement: Интерактивный ввод параметров

Каждое действие SHALL содержать `prompt.js`, который в интерактивном окружении (TTY) запрашивает только отсутствующие параметры: `app-name`, `app-description`, `cut-examples`, `add-web-socket` (переданные флаги SHALL NOT переспрашиваться). В не-интерактивном окружении (без TTY) промпт SHALL завершаться без вопросов, оставляя валидацию недостающих параметров фабрике хелперов. `--root` SHALL NOT запрашиваться интерактивно.

#### Scenario: Недостающие параметры запрашиваются в TTY

- **WHEN** пользователь выполняет `hygen create root,client,server --root=<dir>` в терминале
- **THEN** генератор спрашивает имя, описание и confirm-вопросы (`cut-examples`, `add-web-socket`), но не переспрашивает переданные значения

#### Scenario: Переданные флаги не переспрашиваются

- **WHEN** пользователь выполняет генерацию в TTY с `--app-name=x --app-description=y`
- **THEN** вопросы об имени и описании не задаются

#### Scenario: Не-интерактивный режим без вопросов

- **WHEN** генерация выполняется без TTY (CI/скрипты)
- **THEN** промпт не задаёт вопросов; при отсутствии обязательных параметров фабрика хелперов завершает прогон ошибкой валидации

### Requirement: Обязательный --root

Генератор SHALL требовать явный `--root=<dir>` и SHALL NOT поддерживать рендер in-place (в текущий рабочий каталог по умолчанию).

#### Scenario: --root не указан

- **WHEN** пользователь выполняет `hygen create root` без `--root`
- **THEN** генерация завершается ошибкой до записи любых файлов

#### Scenario: Рендер в указанную папку

- **WHEN** пользователь указывает `--root=<dir>`
- **THEN** все файлы шаблона записываются относительно `<dir>`, каталог создаётся при отсутствии

### Requirement: Guard против рендера в репозиторий шаблона

Генератор SHALL отклонять генерацию, если разрешённый `realpath(--root)` точно совпадает с корнем репозитория шаблона (каталога, содержащего `_templates`).

#### Scenario: --root указывает на репозиторий шаблона

- **WHEN** пользователь выполняет генерацию с `--root`, равным корню репозитория шаблона (или пути, разрешающемуся в него через symlink)
- **THEN** генерация завершается ошибкой до записи любых файлов

#### Scenario: Вложенная папка внутри репозитория шаблона разрешена

- **WHEN** пользователь выполняет генерацию с `--root=tmp` (вложенная папка внутри репозитория шаблона, не совпадающая с его корнем)
- **THEN** генерация выполняется успешно в `tmp/`

### Requirement: Конфигурация через фабрику хелперов

Все производные значения конфигурации (`ROOT`, `APP_NAME`, `APP_DESCRIPTION`, `SERVER_NAME`, `CLIENT_NAME`, `CLIENT`, `SERVER`, `CUT_EXAMPLES`, `ADD_WEB_SOCKET`) SHALL вычисляться в фабрике хелперов `.hygen.js` и быть доступны шаблонам как `h.<ИМЯ>`. `CLIENT` и `SERVER` SHALL вычисляться из списка действий. Валидация обязательных флагов SHALL выполняться в фабрике. Шаблоны SHALL NOT содержать собственного конфигурационного файла-шаблона и SHALL NOT полагаться на глобальные переменные процесса.

#### Scenario: Доступ к конфигурации в шаблоне

- **WHEN** рендерится любой шаблон действия `server`
- **THEN** выражения `h.ROOT`, `h.SERVER_NAME`, `h.APP_NAME` возвращают значения, производные от CLI-флагов

#### Scenario: Значения не зависят от порядка файлов

- **WHEN** действие исполняется (файлы рендерятся в алфавитном порядке путей)
- **THEN** каждый файл получает полные значения конфигурации независимо от позиции относительно других файлов

### Requirement: Внутренняя структура действий как корень приложения

Шаблоны каждого действия SHALL располагаться в каталоге `_templates/create/<action>/` так, чтобы вложенные пути отражали целевую структуру приложения (например, `client/apps/client/webpack.config.js.t`), при этом фактический путь записи SHALL определяться только атрибутом `to:` во frontmatter. Расширение файлов шаблонов SHALL быть `.t`. Имена файлов SHALL NOT содержать числовых префиксов порядка.

#### Scenario: Структура отражает целевое приложение

- **WHEN** разработчик открывает `_templates/create/server/`
- **THEN** он видит иерархию, соответствующую структуре `apps/<name>-server` сгенерированного приложения

### Requirement: Точки порядка a-before и z-after

Каждый полный сценарий генерации SHALL исполнять `a-before.t` до всех остальных файлов действия и `z-after.t` после всех, за счёт алфавитного порядка путей. `z-after.t` SHALL выполнять форматирование сгенерированного кода (prettier) и, на Linux, установку исполняемых прав на `.husky/*`. `a-before.t` SHALL существовать как точка входа для будущих pre-checks и SHALL NOT выполнять действий.

#### Scenario: z-after исполняется последним

- **WHEN** завершается рендер всех файлов действия `root`
- **THEN** сгенерированное дерево отформатировано prettier, а `.husky/*` имеют исполняемые права (на Linux)

#### Scenario: a-before пуст

- **WHEN** начинается рендер действия
- **THEN** `a-before.t` не производит ни записи файлов, ни shell-команд

### Requirement: Удаление флага --hygen и отказ от удаления артефактов

Генератор SHALL NOT поддерживать флаг `--hygen`. Файл `.hygen.js` SHALL записываться в целевую папку безусловно. Генератор SHALL NOT удалять какие-либо артефакты (`doc/`, `.hygen.js`, `_templates/`, `.scripts/`, иные файлы) в целевой папке после генерации. Зависимость в сгенерированном `package.json` SHALL указывать `@biorate/hygen`.

#### Scenario: .hygen.js пишется безусловно

- **WHEN** выполняется генерация действия `root` с любым набором флагов
- **THEN** `<root>/.hygen.js` создаётся с фабрикой хелперов, совместимой с новой конфигурацией

#### Scenario: Никаких удалений после генерации

- **WHEN** генерация всех действий завершена
- **THEN** ни один файл целевой папки не был удалён генератором

### Requirement: Хелперы-гейты не требуются

Атрибуты `to:` шаблонов действий `client` и `server` SHALL NOT использовать условные хелперы-гейты (`h.server()`/`h.client()`), поскольку принадлежность файла действию определяется его расположением в каталоге действия. Хелпер `h.root` SHALL сохраняться для путей, общих для всех действий.

#### Scenario: Прямой to: в шаблонах приложений

- **WHEN** просматривается frontmatter шаблона из `_templates/create/server/apps/server/`
- **THEN** `to:` содержит безусловное выражение пути (например, `${ROOT}/apps/${SERVER_NAME}/...`)

### Requirement: Справка и документация

Команда `hygen create help` SHALL выводить актуальную справку по действиям и флагам. README и AGENTS.md репозитория SHALL описывать новые команды (`hygen create root,client,server`), обязательность `--root`, и SHALL NOT упоминать флаг `--hygen` и скрипт перенумерации шаблонов.

#### Scenario: Справка соответствует структуре

- **WHEN** пользователь выполняет `hygen create help`
- **THEN** справка описывает действия root/client/server и обязательный `--root`, без упоминания `--hygen`

#### Scenario: Пример команды в документации работоспособен

- **WHEN** команда-пример из README выполняется в чистом каталоге
- **THEN** генерация завершается успешно и воспроизводит заявленный результат
