# AGENTS.md — работа с репозиторием `application-template`

Этот файл предназначен для ИИ-агентов и разработчиков: кратко описывает, что это за проект, как его менять и куда смотреть за деталями.

## ОБЯЗАТЕЛЬНЫЙ РАБОЧИЙ ПРОЦЕСС

Перед написанием кода строго следуй алгоритму:

1. Анализ → суть, риски, зависимости, edge-cases
2. План → шаги, файлы, слои, команды проверки
3. Варианты → 2-3 подхода с плюсами/минусами (если применимо)
4. Ожидание → ЗАПРОСИ разрешение. НЕ пиши код до `ОК` или выбора варианта.
5. Реализация → строго по плану. Комментируй только нетривиальные решения.
6. Верификация → команды тестов/линтов, что проверить в UI/API

Запрещено: любая правка в node_modules.
Запрещено: `git commit` и `git push` по собственной инициативе — только
после явного подтверждения пользователя (агент готовит изменения/сообщение
коммита, коммитит и пушит лишь по его «ОК»).

## Что это за проект

**Полнофункциональный шаблон-генератор** fullstack-приложений на TypeScript под экосистему **biorate**. Репозиторий сам по себе — **не** готовое веб-приложение: в корне нет `apps/` и типичных скриптов сборки продукта. Здесь лежат:

- **Hygen-шаблоны** (`_templates/create/{root,client,server,help}/…`) — EJS-файлы (расширение `.t`), из которых при выполнении генератора создаётся монорепозиторий с клиентом и/или сервером.
- **Документация** (`doc/`) — описание архитектуры, конфигурации, коннекторов к БД, брокерам и т.д. (ориентирована на **сгенерированное** приложение, но полезна и при правке шаблонов).
- Конфиг **`.hygen.ts`** — фабрика хелперов (TS, именованный экспорт `export const helpers`; `export default` ломает движок): вычисляет `h.ROOT`, `h.APP_NAME`, `h.SERVER_NAME`, `h.CLIENT_NAME`, `h.CLIENT`, `h.SERVER` и др., выполняет валидацию обязательных флагов и guard против рендера в корень репозитория шаблона.
- **Тесты** (`tests/`) — vitest + `@biorate/vitest`/`@biorate/vitest-spec`; интеграционные тесты через embedding API `runner()` из `@biorate/hygen`.

Сгенерированный стек (см. `README.md` и `doc/`):

| Слой     | Технологии                                                                                                                               |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Сервер   | **NestJS**, **Inversify** через **@biorate/inversion**, порты/use-case’ы, **infrastructure** (HTTP, persistence, WebSocket по опции)     |
| Клиент   | **React**, **MobX**, **react-router**, **i18next**, стили (в т.ч. styled-components, css/less/scss), сборка **Webpack**, шаблоны **Pug** |
| Монорепо | **pnpm** workspaces, **Lerna**, **Nx** (как в генерируемом `package.json`)                                                               |
| Конфиг   | **@biorate/config** (JSON-path, шаблоны `${…}` / `@{…}` / `#{…}`)                                                                        |
| Тесты    | Клиент: **Playwright**; сервер: **Vitest** (unit + e2e, Allure-отчёты)                                                                   |

## Обязательные требования окружения

- **Node.js** ≥ 20
- **pnpm** ≥ 9.7.1 (в `package.json` также указаны совместимые версии npm/yarn)
- **ts-node** ≥ 10.9.2 и **typescript** ^5.0.4 (devDeps; ts-node@10.9.2 несовместим с TS 7 — TS ограничен версией ^5.0.4)
- **enquirer** ^2.3.6 (прямой devDep: TTY-ветка `createPrompter` в `.hygen.ts`; сгенерированной цели он нужен только при запуске генератора в TTY)

## Типичный сценарий: создать приложение из шаблона

Из корня этого репозитория:

```bash
pnpm install
npx hygen create help
npx hygen create root,client,server --root=tmp/my-app --app-name=name-of-the-app --app-description='My app name' --add-web-socket
```

Состав генерации определяется **списком действий** (второй позиционный аргумент); допустим вызов любого подмножества (`root`, `client`, `server`).

Параметры генератора (см. `_templates/create/help/index.t`):

| Флаг                | Назначение                                                                                                                                                                      |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `--root`            | **Обязательный** путь генерации; не может совпадать с корнем репозитория шаблона (guard). Можно тестировать в `tmp/` внутри репозитория, обязательно БЕЗ флага `--cut-examples` |
| `--app-name`        | Имя продукта (используется в именах пакетов: `<app-name>-client`, `<app-name>-server`)                                                                                          |
| `--app-description` | Краткое описание (в т.ч. отображение во вкладке браузера)                                                                                                                       |
| `--cut-examples`    | Убрать примеры из сгенерированного кода                                                                                                                                         |
| `--add-web-socket`  | Добавить WebSocket (Nest gateways + события в шаблоне)                                                                                                                          |

В TTY недостающие параметры запрашиваются интерактивно (декларативная схема `static params` в hook-файлах `hooks.ts` каждого действия: параметры `root`, `app-name`, `app-description` — string, `cut-examples`, `add-web-socket` — boolean с `default: false`, все `required`; params-фаза движка приводит флаги к типам и спрашивает только недостающие required-параметры); в не-интерактивном режиме (CI) все флаги передаются явно — `createPrompter` в `.hygen.ts` возвращает stub-промптер, нарушение контракта даёт быструю ошибку `ParamRequiredError` (enquirer в non-TTY зависает, поэтому не вызывается).

Обязательны `--root`, `--app-name` и `--app-description` (проверка в params-схеме хуков и фабрике; несуществующий `--root` разрешён — guard запрещает только точное совпадение пути с корнем репозитория шаблона, существующий путь сверяется через `realpathSync`).

После генерации рабочая разработка идёт **уже в созданном монорепозитории** (команды из генерируемого README), например:

- `pnpm run build:debug` — dev-сборка клиента
- `pnpm run start:debug` — dev-запуск сервера

## Где что лежит в этом репозитории

| Путь                        | Содержание                                                                                                                                     |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `_templates/create/root/`   | Шаблоны корня монорепозитория; пост-обработка цели (prettier, chmod husky) — в action-хуке `afterAll` класса `_templates/create/root/hooks.ts` |
| `_templates/create/client/` | Шаблоны клиентского приложения; структура зеркалирует целевое дерево `apps/<app-name>-client`                                                  |
| `_templates/create/server/` | Шаблоны серверного приложения; структура зеркалирует целевое дерево `apps/<app-name>-server`                                                   |
| `_templates/create/help/`   | Текст справки для `hygen create help`                                                                                                          |
| `.hygen.ts`                 | Фабрика хелперов (TS, именованный экспорт `export const helpers`; конфигурация, валидация, guard) — конфиг движка этого репозитория            |
| `tests/`                    | Тесты генератора (vitest, embedding API `runner()`)                                                                                            |
| `doc/`                      | Подробная документация по архитектуре и инфраструктуре                                                                                         |

- `ARCHITECTURE.md` — IoC, **@biorate/inversion**, `injectable` / `init` / `kill`
- `APP_STRUCTURE.md` — структура монорепо, клиента и сервера

## Тестирование генератора

Тесты генератора живут в `tests/` — vitest + `@biorate/vitest`/`@biorate/vitest-spec`:
юнит-тесты фабрики `.hygen.ts` (`tests/factory.spec.ts`) и интеграционные тесты
через embedding API `runner()` из `@biorate/hygen` против golden-фикстур
(`tests/runner.spec.ts`). Запуск — `pnpm test`; после изменения шаблонов
обязательна регенерация фикстур (`node tests/__fixtures__/generate-manifests.mjs`).
Подробности — [tests/README.md](./tests/README.md).

## Рекомендации для агентов при изменении шаблонов

1. **Понимать два контекста:** правка **генератора** (файлы в `_templates/`) vs правка **уже сгенерированного** приложения в другом каталоге — это разные задачи.
2. **Порядок исполнения** файлов внутри действия — алфавитный по полному пути (`localeCompare`); числовые префиксы не используются, шаблоны-хаки упорядочивания (`a-before.t`/`z-after.t`) не применяются — пост-обработка живёт в action-хуке `afterAll` класса `hooks.ts` действия root.
3. Шаблоны — **EJS** c расширением `.t`; путь записи выводится из расположения шаблона (`mirror: true`, path macros `$IDENTIFIER$` в именах папок — например `apps/$CLIENT_NAME$/…`), явный `to:` — только для путей, не выводимых из расположения; конфигурация — через фабрику в `.hygen.ts` (`h.ROOT`, `h.APP_NAME`, `h.CLIENT`, …), глобальные переменные процесса не используются. Фабрика `helpers(locals, config)` — единственный механизм трансформации CLI-аргументов в `h.*` (`localsDefaults` движка вычислять производные значения не умеет).
4. **Условная генерация** — списком действий (`root,client,server`) и атрибутом `skip:` во frontmatter (`skip: <%= !h.CLIENT && 'client action not requested' %>`, `skip: <%= h.CUT_EXAMPLES && 'examples cut' %>`, `skip: <%= !h.ADD_WEB_SOCKET && 'web socket not requested' %>`).
5. **Никогда не удалять** генераторные артефакты из целевой папки; фабрика хелперов `.hygen.ts` — единственный конфиг движка и живёт только в корне репозитория шаблона (в сгенерированную цель не доставляется).
6. Учитывать ограничение из `APP_STRUCTURE.md`: CI/пайплайн в текущем виде рассчитан на **одну** пару client/server в монорепо.
7. После изменения шаблонов прогонять тесты (`pnpm test`) и/или diff-матрицу генерации.

## Что получает сгенерированный монорепозиторий

При `hygen create root,client,server` в создаваемый **корень** проекта кладётся **`AGENTS.md`** с глобальными правилами (границы приложений, ошибки, тонкие контроллеры/UI, ссылки). Шаблон: `_templates/create/root/AGENTS.md.t`.

При генерации действия `server` дополнительно создаётся **`apps/<app-name>-server/AGENTS.md`** с правилами сервера (слои, DI, статика, тесты, запреты). Шаблон: `_templates/create/server/apps/server/AGENTS.md.t`.

Подробности по стеку и слоям сервера — в этих файлах у потребителя шаблона; здесь, в репозитории генератора, достаточно не дублировать их и при правке шаблонов **синхронизировать** оба `AGENTS` с целевой архитектурой.

Клиент в генерируемом приложении — **MobX** и **@biorate/inversion**, как на сервере.
